# Changelog

## 0.3.8
- **The wall no longer waits for the slowest data source after a start.** Right after (re)starting — for example after a software update — it showed "live · no data" until *every* source had finished, which could take minutes on a large tenant. Core data (venues, APs, switches, clients, alarms) now appears as soon as it arrives and the slower sources (ports, analytics, event log…) fill in afterwards. Until the first data arrives the chip reads *starting — fetching from RUCKUS One…*.
- **No more hung polls.** Every request to RUCKUS One now has a 45-second deadline (`R1_TIMEOUT_MS`), so one unresponsive call becomes a visible source error instead of stalling the wall, and a watchdog restarts a poll that has been stuck for over five minutes.

## 0.3.7
- **No more openssl dependency.** Self-signed certificates and certificate signing requests (CSRs) are now generated by the app itself, so *Generate self-signed certificate* / *Generate signing request* work the same on Windows (where it previously said "openssl not installed"), macOS and the appliance. RSA 2048 or ECDSA P-256; subject alternative names for hosts and IPv4/IPv6 addresses; verified against `openssl`.

## 0.3.6
- **Fresh installs no longer look broken.** Before any R1 credentials are entered the wall shows a clear *"Not connected to RUCKUS One yet — Open the editor"* banner and a **setup needed** chip instead of a pile of source errors.
- **Stale "credentials not configured" errors cleared.** After saving (or restoring) the connection, cached results from the earlier failed attempt were kept for up to 5 minutes, so *apGroups* / *analytics* kept reporting "R1 credentials not configured" even though everything else worked. Saving the connection now clears those caches, and a failed fetch is retried within about 30 seconds instead of 5 minutes.

## 0.3.5
- **Security fix (appliance):** the web sign-in with the machine's `noc` login now **refuses while the account still has its first-login "must change" password** (`noc` / `noc`). Before, anyone who could reach a freshly imported appliance could sign in to the editor with the default password until someone changed it at the console. Change the password at the console first, then sign in on the web. Existing appliances: update the app, then run `sudo bash /opt/r1-noc/scripts/appliance-auth.sh` once to install the corrected helper (if you already changed the `noc` password you were not exposed).
- The server prints its network addresses at start (`wall: http://<ip>:8080/`) and the docs use `<server-ip>`; the editor also works when you browse to the server's own IP from the server itself, not only `localhost`.
- Repository prepared for publishing: third-party notices (`THIRD_PARTY_NOTICES.md`), `SECURITY.md`, Node.js and Debian license files kept inside the downloads, refreshed screenshots.
- Getting started rewritten around the downloadable releases (appliance, Mac app, Windows) — no Node.js or git clone needed — with the source route as its own path.

## 0.3.4
- Documentation refresh: rewritten README with screenshots, updated Getting started and User guide (current scope, MSP, switch events, install options).
- Editor panels can be deep-linked (`/admin#conn`, `#secPanel`, `#bkPanel`, `#upPanel`, `#authPanel`).
- *Switch events* preset reorganised to fit one screen; *MSP fleet statistics* uses per-customer trend lines that need no extra history.

## 0.3.3
- **Switch event log from R1** (`POST /events/query`, entity type SWITCH, last 7 days): *Switch event log*, *Switch events needing attention* (loops, spanning tree, port, PoE, stack, offline), counts, by kind, by switch, per hour, and an alert metric. Kinds are inferred from the event wording; included in the **Switch events** preset.

## 0.3.2
- **Switching events** (new widget group + **Switch events** preset): *flapping ports*, port link changes, spanning-tree state changes, err-disable events, a recent-events list, noisiest switches/venues and events per hour — derived from the app's own port polling (sampled every few minutes; the log is kept 7 days) — plus *loops detected*, *port-flap* and *TCP SYN flood* incidents and a switching-incident list from R1's analytics service. Works per venue and per customer; three new alert metrics.

## 0.3.1
- **One connection panel.** *R1 connection* now starts with a switch — *One RUCKUS One account* / *MSP — one key for all my customers* / *MSP — a separate key for each customer* — and shows only the fields for the chosen mode. The separate *Customers (MSP)* panel is gone. Existing installs keep working (the mode is worked out from what you had configured).

## 0.3.0
- **MSP account mode** — one API key created in the MSP's own account lists every customer (`/tenants/query`) and reads each one through R1's *delegated access* (`x-rks-tenantid`). No per-customer keys needed (they still work alongside it). Untick customers you don't want on the wall.
- **Fleet statistics across all customers**: a *Customer* dimension on clients, APs, radios, switches, ports, alarms, DPSK, guests and networks (84 generated widgets: counts, throughput, traffic, signal, PoE… by customer, and over time by customer), fleet KPIs and totals, offline/throughput rankings, and an **MSP fleet statistics** preset.
- **MSP rankings, health and trends**: customer health score (with breakdown), AP availability, load, signal, firmware lag and versions, licenses vs devices, connection-experience and incident rankings, busiest venues, and per-customer trend lines; presets *MSP rankings*, *MSP trends*, *MSP fleet detail*.
- New MSP widgets and presets: **MSP licensing** (nearest account/trial expiry, licenses per customer, MSP subscriptions, trial watch), Account and Licenses columns on the Customers overview; alert metrics for account expiry and expiring subscriptions.

## 0.2.1
- **Editor sign-in**: a login page (`/login`) with user name and password instead of the long `?key=` address. On the virtual appliance the machine's **`noc` console login** works; elsewhere create an account in the editor (*Editor login*). Sessions, lockout after repeated failures, sign-out.
- The appliance console banner and menu no longer lead with the key address (the key still works for scripts).
- Existing appliances: update the app from the editor, then run `sudo bash /opt/r1-noc/scripts/appliance-auth.sh` once.

## 0.2.0
- **MSP mode** — one API application per customer tenant; customer filter on every widget; customer-named alerts; `?customer=` walls.
- **Client experience analytics** (experimental) — connection success by stage, time to connect, incidents, top applications/SSIDs/APs/clients, failures by SSID/AP/client maker, roaming, client signal, AP uptime, per-venue.
- **HTTPS and certificate management** — self-signed certificates, CSR generation, install a CA-signed certificate, redirect, HSTS, expiry alert.
- **Backup and restore** — configuration-only (credential-free) or full encrypted backups; automatic daily copy; restore with a safety snapshot.
- **In-place upgrade** from a downloaded release file, with a start-up test, automatic backup of the old version and one-click rollback.
- Renamed to **R1 NOC Wall**.
